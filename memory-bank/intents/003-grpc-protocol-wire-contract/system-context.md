# System Context: gRPC Protocol & Wire Contract

## Overview

`firma-proto` defines the wire contract — the Protobuf service definitions and message types that all Firma components communicate through. It is a pure protocol crate with no runtime behavior.

## System Boundary

```text
                         ┌────────────────────────────┐
                         │      firma-proto           │
                         │  (wire contract only)      │
                         │                            │
                         │  ┌──────────────────────┐  │
                         │  │ AuthorityService     │  │
                         │  │  - IssueCapability   │  │
                         │  │  - WatchPolicyBundle │  │
                         │  │  - WatchRevocations  │  │
                         │  └──────────────────────┘  │
                         │                            │
                         │  ┌──────────────────────┐  │
                         │  │ Shared Messages      │  │
                         │  │  - ExecutionEnvelope │  │
                         │  │  - CapabilityToken   │  │
                         │  │  - PolicyBundle      │  │
                         │  │  - RevocationEvent   │  │
                         │  └──────────────────────┘  │
                         └────────────────────────────┘
                            ▲                    ▲
                            │                    │
                   ┌────────┴──────┐    ┌───────┴─────────┐
                   │ firma-sidecar │    │ firma-authority │
                   │   (client)    │    │   (server)      │
                   └───────────────┘    └─────────────────┘
```

## Actors

| Actor | Role | Interaction |
|-------|------|-------------|
| `firma-sidecar` | gRPC client | Calls `IssueCapability`, subscribes to `WatchPolicyBundle` and `WatchRevocations` streams |
| `firma-authority` | gRPC server | Implements `AuthorityService` trait generated by tonic |
| Agent (indirect) | Triggers capability issuance | Does not interact with proto directly — communicates via HTTP through sidecar |

## What This Intent Does NOT Do

- No server or client implementation (that's intents 005 and 006)
- No runtime behavior
- No Cedar policy evaluation
- No token signing/validation (that's intent 002, `firma-core`)
- No connector logic (that's intent 006)
